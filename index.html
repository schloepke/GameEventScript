Messages connect the pieces

Handlers react to named messages and emit new ones. Your application supplies native actions, data and the starting event.

02

State stays with you

Script values are immutable. Your application owns persistent state and decides what scripts can see through explicit native bindings.

A shared contract

C# and Swift implement the same language and portable program format, checked against a shared Markdown conformance corpus.

Schemas, models, documents and generated code

Describe your data once.

One schema gives you exact bit-level encoding for the network, typed models your program keeps, checked data files for your content and typed code for C# and Swift.

01

Schemas .gess

Ranges, steps and units decide the bits of every field. Packed records fit in one machine word, and deltas send only what changed since the last full record.

02

Models

Mark a schema as a model and get the data your program keeps: a Swift struct that is Hashable, Sendable and Codable, a C# class that compares by value. Server, client, tools and scripts share one definition of each view.

Client and server sessions New in 0.6.0

From schema to session.

Declare which records client and server exchange. GES Network sends them in as few bits as their schema allows, and states only as far as they changed, over TCP, WebSocket or UDP, encrypted, in C# and Swift.

01

Routes with a delivery class

Each route is reliable, latest or bulk: every command in order, only the newest state, or large transfers behind all other traffic. The handshake compares the schema hash, so an outdated client never misreads the server.

Connect a client and a server →
02

Only what changed

A published state travels as a delta against the last state the client confirmed, or as the full record when that is shorter. Records carry no names or tags, small messages share packets, and the server decides which client receives which topic.

Publish states →
03

Sockets and encryption

Socket packages run sessions over TCP, WebSocket and UDP. UDP resends what was lost and keeps the order of reliable routes. A server key encrypts every session with X25519 and ChaCha20-Poly1305.

Connect over TCP →
04

Your loop, your clock

The session core opens no socket, starts no thread and reads no clock. Pairs connect both sides in one process for tests and single player, and a seeded simulator reproduces latency and packet loss.
