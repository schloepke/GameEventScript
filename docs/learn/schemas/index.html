Describe data with schemas

Since: Unreleased

A schema (.gess) describes what your data looks like: which fields exist, in which range and how precise they are. From that one description you get two things:

  • a very compact binary encoding, for example to send game state from a server to its clients;
  • a check of GES documents (.gesd), for example your configuration files.

This guide builds a schema step by step. Schemas defines the exact rules.

1. A first schema

Save this as game.gess:

A range and a step decide how many bits a field takes. A record holds only these bits, with no field names, type tags or units:

Field Possible values Bits
id 1024 10
x 5001, every 10 cm from 0 m to 500 m 13
y 5001 13
heading 360, since 360° is the same point as 0° 9
health 101 7
shielded 2 1

That makes 53 bits, so a Player always takes 7 bytes. Sender and receiver can only read this because both hold the same schema.

2. Choose ranges and steps

Each number needs a decision about how exact it has to be:

  • integer keeps whole numbers exact.
  • step rounds to a multiple: x above is exact to 10 cm. The narrower the range and the coarser the step, the fewer bits it takes. This loss is what you declare; both sides round the same way.
  • between a and b includes both ends. A value outside is an error for the caller. Nothing is clamped silently.
  • wrapping between a and b is a circle, for angles. -90° is stored as 270°.
  • A fractional number without a step always takes 64 bits.

Literals are written in their field’s unit. Prefixes are only spelling: :Quantity(N) between 0kN and 50kN is valid, :Quantity(kN) is not.

3. Use the other field types

  • :Tag(...) is one tag of a closed set, stored as its index: 2 bits for kind. :Tag max 32 allows any tag of up to 32 characters, stored like a Text: 6 bits and 8 per character. Prefer a closed set for data you send often.
  • :Text max n and :List(T) max n store a count, then their contents. max counts UTF-8 bytes or elements, and without it a field cannot be encoded.
  • :Dice max 5 between 1 and 20 stores up to 5 rolls in 5 bits each, here for a d20. Without a range a roll takes 31 bits. A Dice value always holds its rolls sorted, whatever their order in the data.
  • optional adds one presence bit. An absent value reads as nothing.
  • :Point and :Vector list the axes they transmit. An axis left out is not sent and must be zero.
  • :Weapon refers to another schema, whose fields follow inline. References cannot form a cycle.

A boolean flag is simply a :Boolean field and takes one bit.

A field can also hold one of several types. Such a union stores the index of the alternative, then its value. The kind of a value selects the alternative, so alternatives must differ in their type name:

facing takes 1 + 9 bits for an angle and 1 + 1 bits for a tag. :Nothing takes no bits of its own, so note may be left out like an optional field, and this also works for list elements: :List(:Text max 8 | :Nothing) max 4.

4. Share values with constants and parameters

A constant is a name for a literal in this file. A parameter is decided later, for example per map. You supply it when you bind the schema:

Each binding fixes all widths, here 19 bits for x and y. You can bind one schema several times with different values, for two zones of different size in one session. The wire does not say which binding a record uses, so choose it from your own context, such as the connection.

5. Find the object with a key

key marks the first field of a schema as the identity of the object, like id of Player. It is written at bit 0, so a receiver can read it first and then decide what to do with the rest. A key is an integer number or a :Tag with a set, and it cannot be optional.

6. Describe messages

A message has a name, ordered arguments and optional tags, like a message in a GES script:

  • target is a labeled argument, as in Hit(target: 7, 25). With _, as in _ damage, the argument has no label; the name then only identifies it in your code.
  • Each declared tag takes one bit, since any combination may be present.
  • The name of the message is not transmitted.

A Hit takes 16 + 10 + 2 = 28 bits. That only works if the receiver already knows that a Hit comes next, for example on a channel that carries nothing else.

7. Choose between messages with a message set

Usually one stream carries different messages, and the receiver has to find out which one comes. That is what a message set declares:

messages :Combat as (Hit, Died) says: a record of Combat is exactly one of these messages. Its encoding starts with the index of the message in this list, which takes 1 bit for two messages, and the message follows:

Record Bits Bytes
Hit in Combat 1 + 28 = 29 4
Died in Combat 1 + 16 = 17 3

The order in the list matters, because it decides the index; changing it changes the hash. A message may belong to several sets, for example one per channel. A set is not a data type: a field cannot have the type :Combat. You encode and decode it as the root of a record.

8. How it runs

A schema is data your program reads at run time, and needs neither a compiler nor a VM for it. If you prefer typed code, you can generate it instead; the bytes are the same:

Step C# Result
Read the sources, once GesSchemaSet.Parse(sources) all declarations, checked
Pick a declaration schemas.Schema("Combat") a description with its hash
Bind parameters, per session or map .Bind(parameters) the widths and layout, immutable and shareable
Resolve fields, once bound.Member("Hit").Field("target") handles that cost no lookup later
Write or read each record GesSchemaWriter, GesSchemaReader bytes in your buffer, without allocations

Fields are written and read in declaration order; anything else is the error wire.fieldOrder. A union alternative has its own handle, such as facing:Tag, after SelectAlternative or ReadAlternative. This writes and reads the Combat set in C#:

stackalloc suits a small schema like this one, whose largest encoding takes a few bytes. MaxByteCount can reach 10 MiB, more than a thread’s stack holds, so for large schemas keep one buffer per connection or take it from a pool.

And the same in Swift, which follows the same steps with its own spelling:

For rare data where convenience matters more than speed, GesSchemaValues encodes and decodes a whole Record, Map or Message at once. A decoded Bot is a Record with the type name Bot.

9. Compare the hash at connection setup

Both sides must hold the same schema and the same parameter values, because nothing on the wire describes the data. A record has no header and no length either, so your transport frames it. Each declaration has a hash for this, which you compare when a connection starts:

  • bound.Hash changes with field order, types, bounds and steps. It ignores comments, layout and the spelling of literals, so 50kN and 50000N hash alike.
  • bound.BindingHash also covers the parameter values.

There is no compatibility between different hashes: if they differ, the two sides cannot talk. The hash detects mistakes and is no security measure. Data from a peer stays untrusted, and the decoder rejects anything outside the schema.

12. Send only what changed

A record that mostly repeats is cheaper as a delta. delta within declares the largest change you expect between two updates, in the units of the field, and a change within it takes only a few bits:

A full record takes 8 + 13 + 13 = 34 bits, 5 bytes. A delta has the key and one change bit per field, and a small move takes 7 bits per axis: 8 + 2 + 7 + 7 = 24 bits, 3 bytes. A larger move still works and takes 14 bits for that axis.

Decode writes the full record again, so a receiver keeps it as its next baseline. A key comes first in a delta as well, so a receiver can find the object’s baseline with ReadKey before it decodes the rest. Which record counts as confirmed is up to your game, since nothing on the wire marks a delta. For rare data, GesSchemaValues takes a baseline value instead. ges schema dump --baseline makes a delta readable. See Deltas for the exact form.

A list usually goes whole, since nothing tells its elements apart. A list of a schema with a key is different: its delta names the removed positions, the added elements and a nested delta for each changed one, so moving one drone in a list of fifty costs a few bytes rather than the whole list:

This needs no extra syntax, but it needs your help: keep such lists sorted by key in every record. If the keys of the baseline or the new record do not strictly ascend, the delta falls back to the whole list, which stays correct but saves nothing. See Keyed lists.

13. Generate typed code

Since: Unreleased

The writer and reader look fields up through handles. When your schemas are fixed at build time, ges schema generate writes a type per schema instead, with fields you assign directly and the parameters as constants:

For the :Fleet of the previous section, Drone becomes a struct and Fleet a class, because its list needs storage. The code writes and reads the same bytes, with the same errors, as the writer and reader, deltas included:

A class keeps its storage, so once it has held its largest data, writing and reading allocate nothing. A baseline therefore needs its own storage: fill it with CopyFrom rather than assigning the list of the record that reads, which ReadDelta rejects with wire.overlappingBuffers in debug builds and builds that define GES_CHECK_SHARING, and for generated C# also in Unity’s editor and development players. Records compare by what goes on the wire with WireEquals, and Quantize rounds a record to the values a receiver reads. --values adds the conversion to GES values and messages for data from scripts. Generated C# is C# 9 and runs in Unity; generated Swift needs no Foundation. Check the files in and add --check to your build, so that a schema change cannot leave stale code behind. The generated code needs Runtime only. To generate from your own build tool rather than the CLI, use the Generator package (GameEventScript.Generator, Swift GameEventScriptGenerator), which your game does not ship. See Tools for the exact shape.

What schemas leave to you

Transport, channels, deciding which objects a client receives and splitting large data all belong to your game. Extension points names where they attach.
