Learn Game Event Script

Write a rule, send it a message, and let your application handle the result. Game Event Script (GES) is designed for this event-driven workflow: scripts describe decisions, while your C# or Swift application owns the game world.

This guide follows the current development checkout. Features marked Unreleased require a build from that checkout until the next package release. The changelog identifies changes since the last release.

The CLI sends Main(args) once. That handler enqueues Hit(amount). When the current message finishes, the host delivers Hit and eventually delivers ConsoleOut to the CLI. An emit queues work; it is not a synchronous call to another handler. ConsoleOut is supplied by the CLI, not built into the language.

An embedded application chooses its own starting message and native handlers. Continue with C# or Swift to run the same kind of flow inside your product.

Names and message arguments

Messages and types start with uppercase letters: Hit, :Number. Local names, functions and tags start with lowercase letters: amount, damage, #critical. A module name such as tutorial.damage identifies the program; it does not create a namespace.

Argument labels are part of a message or function’s signature:

damage(base: 30, bonus: 12) matches damage(base, bonus). double(21) is positional because _ value declares an unlabeled argument. Keep named argument order consistent: labels and their order participate in signature matching.

Values and local bindings

Use let name be expression to bind a value. Bindings are immutable: compute a new value instead of assigning to an existing name.

Common data values include Number, Boolean, Text, Tag, List, Map and nothing. Numbers may carry seconds (0.2s), meters (10m) or degrees (90°). A percentage such as 20% represents the ratio 0.2, so 100 * 20% gives 20.

Adding a Percentage to a Number applies a relative increase: base + bonus means base + base * bonus. The example therefore prints Damage: 120, while base remains 100. Similarly, 100 - 20% gives 80. The Percentage type matters: 100 + 0.2 is ordinary addition and gives 100.2.

There is no mutable global script state. Each handler invocation has fresh local bindings. Keep persistent state in your application, or pass immutable data along in subsequent messages.

Lists preserve element order. Selectors express filtering, projection and aggregation without mutable loop variables:

Schedule work and communicate

emit delivers locally. publish also crosses the configured host publish boundary. Publishing does not automatically provide networking: your embedding supplies the sink and decides how messages reach other hosts.

The CLI waits for delayed work in batch mode. Embedded hosts remain synchronous: your application’s event loop or optional bridge runner resumes processing when work becomes due. emit after 10 Ready() is invalid because 10 has no time unit.

Explore and debug

Use dotnet ges instead of ges with the C# tool. In the interactive console, :help lists commands, :load damage.ges adds a program, and emit Main(args: []) sends its starting message. :handler lists registered handlers; :source and :dump inspect a selected module. Ctrl+N inserts a newline; Enter submits input. Temporary input bindings do not persist between submissions.

For exact syntax, read the language reference. For message ordering, initialization, limits and timing, read the host runtime contract. The CLI guide covers commands and terminal behavior in full.
