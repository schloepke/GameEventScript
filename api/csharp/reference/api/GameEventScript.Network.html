Namespace GameEventScript.Network

Classes

GesNetworkClientEnd

The client end of a session: it owns one client connection and its transport and drives both from Poll<THandler>(ref THandler). Sends, publishes and ticks made before the session is established wait in the end and reach the connection when it connects. One caller at a time; not thread-affine.

GesNetworkClientSecurity

How a client protects its session: with the server's pinned public key, encrypted with a key the server sends during the handshake, or not at all. Immutable; safe to share between connections.

GesNetworkCodes

The codes a connection closes or cancels a transfer with. Each is stable and language-neutral.

GesNetworkConnection

One side of a network session: a synchronous state machine without threads, sockets or clocks. The host passes received bytes and the current time, takes events and takes packets to transmit. Times are microseconds of a monotonic clock chosen by the host. Not thread-safe; one caller at a time.

GesNetworkCookies

The address validation gate of a datagram server: it answers a client it does not know without keeping state, so a forged source address gains no connection. A cookie is the time window number and an HMAC-SHA256 of it and the address with a secret key; the current and the previous window are valid. Not thread-safe; one caller at a time.

GesNetworkKey

A server's static X25519 key pair, which encrypts its sessions. The client receives the public key from outside the protocol and pins it. Immutable; safe to share between connections.

GesNetworkOptions

The limits and transport of one connection. Values are checked when a connection is created.

GesNetworkPair

A client end and a server end connected within one process, without sockets. A realtime pair runs on the system clock and moves packets when the ends poll. A synchronous pair runs on a virtual clock, is connected when created and moves every packet before a send, publish, tick, close or poll returns: what one end sends is reported by the other end's next poll. In both modes a packet waits while the receiving connection takes no further bytes, in a synchronous pair until the host advances the clock far enough to refill its frame bucket; while 64 packets wait, the sending connection keeps its further packets. Both ends of a pair belong to one caller at a time.

GesNetworkServerEnd

The server end of a session: it accepts clients from an acceptor, owns one server connection per client and drives all of them from Poll<THandler>(ref THandler). Clients have stable end-local ids. Publishes and ticks reach every client. One caller at a time; not thread-affine.

GesNetworkServerSecurity

How a server protects its sessions: with its static key, or not at all. Immutable; safe to share between connections.

GesNetworkSimulator

Connects a client and a server connection in one process with seeded latency. Each packet is delayed by the latency plus a draw from 0 to the jitter inclusive, but never arrives before a packet sent earlier in the same direction. Between datagram connections it may also lose, duplicate and reorder packets. Equal seeds, options and inputs give equal packets, events and times. The host takes the events of both connections between calls of Advance(long). Not thread-safe.
