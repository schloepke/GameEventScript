Changelog

User-visible changes and migration guidance are collected here before each release. Entries under Unreleased are available on the development branch; they are not yet included in a published package. Published release notes are available on GitHub Releases.

Unreleased

[0.5.0] — 2026-11-16

This release adds GES schemas (.gess) with exact bit-level encoding, deltas and generated C# and Swift code, GES documents (.gesd), the Bytes type, the shared Syntax module and the Generator package, and gives the C# and Swift ports the same public names and byte-identical compiler output.

Breaking

  • Line breaks inside any parentheses or square brackets separate nothing, so parameter lists, selectors such as [:take highest⏎1] and parenthesized expressions may span lines in both ports; inside braces they separate statements as before.

  • The Swift parser rejects what the C# reference rejects: an operator tighter than the type operation after as, is or has value (a as :Number + 1), a second superscript or ^ after a power (a²², a² ^ b), :Numeric as a type, 5%abc and 90°x, roll without dice, and a dice count on the next line. Calls and lists count the nesting of their arguments and items, so deeply nested chains report parse.sourceNestingExceeded instead of exhausting the stack.

  • Program segment and section types (GesStringConstantSegment, GesCodeSegment, GesSourceMapSegment and the others) have no public constructors and their SliceEntry values no public setters; Programs come only from the Compiler and the Reader. Swift keeps those initializers behind @_spi(Compiler).

  • Program validation rejects binding argument names with a _number suffix and a second Record binding of the same name or a Record binding without an ID (InvalidProgram). A message-name handler records the label message whatever its source binding is called.

  • The new runtime limit MaxValueDepth (default 64) stops a handler that nests Lists, Maps, Records or Messages more than 64 levels deep, which could otherwise overflow the native stack when the value was converted, compared or released. Raise it in GesRuntimeLimits where deeper values are needed.

  • :contains any and :contains all with a Range of candidates, has any/has all over a binary64 Range and starts with/ends with between two Ranges charge MaxLoopIterations for every Range item they visit, and shuffling a Range longer than MaxRangeItems reports that limit and gives an empty List, as as :List does.

  • An external type’s constructor parameter or field declared as a plain Number (Float without a unit) keeps a Quantity’s unit instead of dropping it, as an unconstrained Point or Vector already did: 5m stays 5m as binary64. Declare a unit to convert, or convert the value in the host.

  • Swift [UInt8] converts to and from GES Bytes instead of a List of numbers.

  • Text such as "0x10" is now a hexadecimal number for parse, as :Number, as :Percentage, documents and Message JSON instead of Text or nothing.

  • C# GesValue.AsMap() returns only stored Map and Record data, as in Swift; an external value gives null. MaterializedMap() reads its fields.

  • :Vector(value) and :Point(value) with one positional argument are now the cast, so :Vector([1, 2]) is 1, 2, 0 instead of nothing and :Vector(:Dice[6, 3]) is 6, 3, 0 instead of 9, 0, 0.

  • :Message rejects the labels value and tags in source; use with.

  • The literal nothing and a constant with that value are no tags: this is the new validate.invalidTag, and a tag value that is nothing at runtime makes the tag clause invalid instead of adding #nothing.

  • A send with an invalid tag clause sends nothing and continues; a result-bearing send is false. A statement send used to end the handler, in C# always and in Swift for a Message value.

  • Message names start uppercase: initialization and undeliverable are entry points only the host uses. parse and documents no longer recognize :Message(initialization()) and :Handler(undeliverable()), and in source a lowercase name is a variable or a call of a function or predicate. GameEventScriptMessage.Create and FromJson reject those names, CreateMessage returns nothing for them, and loading a Program with such an outbound binding or message shape fails.

  • A labeled :Range needs from and to, so :Range(from: 1) is an error.

  • value as :Record is validate.invalidTypeConstructor instead of a compiler failure with decode.invalidOperand.

  • Handlers print a space after each comma: :Handler(Done(value, _)).

  • Labeled Vector and Point components must be a run without gaps: :Vector(x: 1, z: 2) is validate.invalidTypeConstructor in source, stays Text for parse and is document.invalidLiteral in documents. The literals true and false are no components either, though a Boolean variable counts as 0 or 1. ConstructData no longer accepts vector and point. CreateVector and CreatePoint use ImmediateX 3 for labeled x, which never lifts; values above 3 fail validation. Recompile .gesb files to get the :Vector(x: v, y: 3) fix.

  • A bare name without a visible binding of its own source is now the validation diagnostic validate.unresolvedVariable at the name, reported for every such name, instead of the first compile.unresolvedSymbol of lowering. The Syntax module reports it too, so editors see it while typing. $constants, calls, extension calls and inline-assembly operands are not affected; an unknown $constant remains compile.unresolvedSymbol.

  • Validation reports the rules of each source on its own first, source by source and in source order of their positions: spelling of names and labels, repeated parameters, arguments, fields and bindings, shadowing, system endpoint forms and removed type names. The program-wide rules follow. A program with errors of both kinds therefore lists its diagnostics in a new order; their codes and positions are unchanged.

  • The optional highlighter packages are renamed to the Syntax module, which will hold the shared lexer, parser and syntax tree: NuGet GameEventScript.SyntaxHighlighter becomes GameEventScript.Syntax (namespace GameEventScript.Syntax), and the SwiftPM product and module GameEventScriptSyntaxHighlighter become GameEventScriptSyntax. Type names such as GesSyntaxHighlighter are unchanged. Migrate by replacing the package reference and the using/import.

  • Highlighting is derived from the lossless syntax tree instead of the bundled TextMate grammars, in both ports. Spans carry a category and the diagnostics overlapping them, and GesHighlightResult.Diagnostics/diagnostics lists the document’s syntax errors or, without those, its violated single-source rules as new GesHighlightDiagnostic values with UTF-16 ranges. The line API (HighlightLine/highlightLine), GesHighlightState, NextState/nextState, CreateState/makeState and the TextMate Scopes/scopes are removed; highlight the whole document after an edit and theme by Kind/kind. Swift GesHighlightingError loses expectedSingleLine and incompatibleState. Some categories become more precise: function and predicate names are Function, contextual keywords such as between, from or ascending are Keyword, brackets and braces are Symbol, extension names are Builtin, and GESA label definitions are Label. Input with statements outside a handler, as console input has, keeps its statement categories. The Swift module no longer imports Foundation, and scripts/sync-highlighter-grammars.py is removed; the TextMate grammars remain for the editor bundles.

  • Runtime now depends on the Syntax module, which owns the quantity unit table and the text and name rules. GesQuantityUnit and GesQuantityUnits move to the Syntax assembly in C# with the unchanged namespace GameEventScript.Api; Swift Runtime re-exports GesQuantityUnit, so source code is unchanged. The NuGet Runtime, Compiler and CSharpBridge packages declare the Syntax dependency, and the runtime, compiler and unity DLL sets now include GameEventScript.Syntax.dll, which manual DLL installations must copy too.

  • parse materializes at most MaxRangeItems Range items into Lists per invocation in total, so many :List(:Range(...)) forms in one Text cannot multiply the per-Range limit. Exceeding the total stops the handler with the MaxRangeItems runtime limit. This includes a single Range longer than the limit, such as parse ":List(:Range(1, 10001))" with the default limit, which previously produced an empty List and let the handler continue. Migrate by raising MaxRangeItems or keeping such Ranges lazy, for example :Range(1, 10001) without :List(...).

  • strict directly after parse is now the strict mode word. To parse a binding named strict, write parse (strict); parse strict alone is a syntax error.

  • A number directly followed by a unit spelling is now one quantity literal, so 10m/s, 6m/s² or 120°/s are a speed, an acceleration and an angular speed rather than divisions by a binding s, 2/s is the rate 2Hz, and 2m² or 2m^2 is an area rather than the square of 2m. Write 10m / s or 2 / s with whitespace to divide and (2m)² to square. Text such as '250ms' now parses as 0.25s instead of failing.

  • floor, ceil, truncate and the three round forms keep the unit of a quantity, at runtime and in constant folding: floor 2.5m is now 2m instead of the unitless 2, and round half even 2.5m/s is 2m/s. Percentages still round to unitless numbers. A rounded time such as floor 1.5s is therefore a valid send delay. Remove the unit explicitly with as :Quantity(none) where a plain number is needed.

  • Swift GesQuantityUnit has new cases for the added physical units, so an exhaustive switch over it must handle kilogram, newton, joule, watt, volt, ampere, hertz, squareMeter, cubicMeter, wattPerSquareMeter, kelvin, degreePerSecond, decibel, wattPerKelvin and joulePerKelvin (or add a default). C# GesQuantityUnit gains the same members; existing values keep their numbers.

  • Runtime observer callbacks report the host-local send ID of the message they describe: C# MessageEmitted(message, id, accepted), MessagePublished(message, id, result), DispatchStarted(message, id, dispatchSignatureId) and DispatchCompleted(message, id, dispatchSignatureId); Swift messageEmitted(_:id:accepted:), messagePublished(_:id:result:), dispatchStarted(_:id:signatureID:) and dispatchCompleted(_:id:signatureID:). Every queued emit or received message, processed publish, delayed send and initialization gets the next ID of its host, so a trace can match each dispatch to its emit, publish or delayed send; 0 marks an emit that was not queued or a publish the host did not accept. Messages themselves carry no ID. Migrate by adding the id parameter: every callback now has an empty default implementation in both ports, so an observer that keeps an old signature still compiles but no longer receives that callback.

  • Public API types are renamed so that only the three edge types keep the GameEventScript prefix: GameEventScriptHost, GameEventScriptProgram and GameEventScriptMessage. All other public types use Ges, identically in C# and Swift, for example GesContext, GesHostBuilder, GesMessageArgument, GesRuntimeLimits, IGesPublishSink (Swift: GesPublishSink) and GesSyntaxHighlighter. Deviating names: GameEventScriptBuilder becomes GesProgramBuilder, GameEventScriptInstance becomes GesProgramInstance, the C# GameEventScriptBytecodeInstructionUnit and Swift GesUnit become GesQuantityUnit, the concrete GameEventScriptExternalTypeCatalog becomes GesDeclaredExternalTypeCatalog (the C# interface is IGesExternalTypeCatalog, the Swift protocol GesExternalTypeCatalog), Swift GameEventScriptExtensionFault becomes GesExtensionFaultError and Swift GameEventScriptAPIError becomes GesApiError. Behavior is unchanged; migrate by renaming references.

  • Builders are created directly or through their target type, following each language’s idiom. C#: new GesProgramBuilder() (the static Create() is removed) or, with C# 14, GameEventScriptProgram.CreateBuilder(); hosts via new GesHostBuilder() or GameEventScriptHost.CreateBuilder(). Swift: GesProgramBuilder() or GameEventScriptProgram.makeBuilder() (create() is removed); hosts via GesHostBuilder() or GameEventScriptHost.makeBuilder() (formerly createBuilder()). The Swift GameEventScriptHost initializer is no longer public; configure hosts through the builder. Swift factory methods use make: GesMessageSignature.makeMessage(_:) and makeSignatureId(name:parameterNames:).

  • Reading, encoding, validating and dumping Programs are members of GameEventScriptProgram; the separate reader, writer, validator and dumper types are no longer public. C#: GameEventScriptProgram.Read(bytes, options), program.Encode() (formerly ToArray), program.GetEncodedSize(), program.Write(destination), program.Validate() and program.Dump(...). Swift: GameEventScriptProgram.read(_:options:), program.encode() (formerly bytes), program.encodedSize(), program.write(into:), program.validate() and program.dump(includeInstructionAddresses:).

  • The Swift Program exposes the same segments as C#: metadata, stringConstants, uint16IndexLists, bindings, code, debugSymbols, sourceMap, sourceArchive and buildMetadata are segment types (GesStringConstantSegment, GesBindingSegment, GesCodeSegment, …) that are also random-access collections over their entries. The binding entry type is GesBindingSegment.Entry in both languages (formerly C# GameEventScriptBinaryBindEntry, Swift GameEventScriptBinding); Swift GameEventScriptSourceMap and GameEventScriptBuildMetadata become GesSourceMapSegment and GesBuildMetadataSegment. Swift GesDebugInfoOptions moves from the Compiler to the Runtime module, as in C#.

  • Message and value JSON are members of the encoded types; GameEventScriptMessageJson is removed. C#: message.ToJson(), GameEventScriptMessage.FromJson(json), value.ToJson() and GesValue.FromJson(json). Swift: message.json(), GameEventScriptMessage(json:), value.json() and GesValue(json:).

  • GesSymbolKind is renamed to GesDiagnosticSymbolKind in both languages to separate it from GesDebugSymbolKind.

  • Swift gains GesDiagnosticCodes with the same stable codes as C#, and GesOpaqueSection.flags is a GesSectionFlags option set instead of a raw UInt16, as in C#. The C# GesInstructionFlag enum is no longer public; both languages expose the raw UnitAndFlags/unitAndFlags byte.

  • Bridge types use the GesBridge prefix and identical names for shared roles: GesBridgeHostRunner, GesBridgeExtensionRegistry, GesBridgeExternalTypeRegistry, GesBridgeMessageHandler, GesBridgePublishSink and GesBridgeValueConversion (formerly GameEventScriptCSharp…/GameEventScriptSwift…). C# registries are created with GesBridgeExtensionRegistry.Create(types)/CreateBuilder() and GesBridgeExternalTypeRegistry.Create(types); the static GameEventScriptCSharpExtensions and GameEventScriptCSharpExternalTypes entry classes are removed. C# gains the public GesBridgeMessageHandler and GesBridgePublishSink delegate adapters. Swift descriptors become GesBridgeFieldBinding<Root>, GesBridgeConstructorBinding<Root>, GesBridgeTypeBinding<Root> and GesBridgeAnyTypeBinding; GesBridgeValueConvertible, GesBridgeConversionError and GesBridgeHostRunnerRegistration replace their GameEventScriptSwift… predecessors. Attributes and macros keep their names.

  • Swift bridge members no longer name the language: setSwiftValue(_:), swiftValue(at:as:), withSwiftArguments(_:) and the swiftArguments: labels of message, emit and publish conveniences become setNativeValue(_:), nativeValue(at:as:), withNativeArguments(_:) and nativeArguments:.

  • Swift no longer exposes runtime helper types that C# keeps internal: GesNumber, GesText and GesSpatialValue (use GesValue.x/y/z) are internal, and GesSeriesValue with GesValue.series(_:)/seriesValue is available only to the Compiler.

  • Swift reports the public value kind as GesValue.valueKind: GesBytecodeTypeKind, the same single type C# uses for ValueKind; GesValueKind and kind are no longer public. Integer and binary64 ranges are both .range (use integerRangeValue/floatRangeValue), and records and external values are .custom. GesMessageArguments.kindAt(_:) returns GesBytecodeTypeKind.

  • Swift maps follow the C# model of sorted keys with parallel values: GesValue.map(keys:values:) and GesValue.record(typeName:keys:values:) create them, and GesValueMap.key(at:)/value(at:) read them next to length, get(_:) and containsKey(_:). GesMapEntry, GesValueMap.entries and GesValue.mapEntries are no longer public.

  • C# GesValueMap.StorageLength is removed; it always equaled Length. Use Length instead.

  • Attributed C# extension parameters check units: a [GesParam] with a unit requires exactly that unit, and one without a unit a unitless argument; another unit gives nothing.

  • The C# GesBridgeHostRunner returns a runner-owned GesBridgeHostRunnerRegistration from Load and Subscribe, as the Swift runner does; its IsAttached, StartResult and Detach() take the runner’s lock. GetStartResult, Detach(instance) and Unsubscribe(subscription) are removed, since the host’s own handles bypassed the lock.

  • C# attributed extensions convert arguments strictly, as Swift does: a fraction, a Boolean or a Percentage no longer converts to an integer or number parameter, and a number no longer to a bool; such a call gives nothing.

  • C# GesBridgeExternalTypeRegistry.Create rejects fields and constructor parameters of CLR types without a conversion, such as decimal or enums, and external classes it does not register. A constructor argument that does not convert exactly, such as 2.7 for an int, is now runtime.externalConstructorFailed instead of a truncated value.

  • The end of console input (EOF) delivers scheduled delayed messages before the CLI exits, as a batch run does, so piped console scripts lose no timer or delayed ErrorCode; :quit still discards them.

  • Host configuration names now say what they configure, before 1.0 freezes them: MaxProcessedEventsPerRun is MaxProcessedMessagesPerRun, MaxQueuedMessagesPerRun is MaxQueuedMessages (it bounds the host’s persistent queue, not one run), and WithRegistry / withRegistry is WithExtensionRegistry / withExtensionRegistry. Observer callbacks and diagnostics report the new limit names.

  • C# removes GesValue.AsNumeric, which duplicated AsNumber(), and GesValue.GesNumber, an alias of GesFloat.

  • Swift GesContext.extensionRegistry is no longer optional: a host without extensions has an empty registry, as in C#.

  • C# GesPoint and GesVector compare components with binary64 equality, as Swift does, so a NaN component makes two values unequal.

Added

  • Schema computed fields take the script language’s functions and powers: sqrt/√, cbrt/∛, sin, cos, tan, asin, acos, atan, atan2, hypot, exp, ln, ^, ², ³, floor, ceil, truncate, round half …, rad and deg, with the language’s units (the root of m² is m). A square root is correctly rounded and bit-identical everywhere; the other functions may differ in their last bits between platforms, as in scripts. A field named like a GES keyword is read in backticks, such as `length` / 2.

  • Names in backticks: any GES keyword written in backticks is a plain name wherever a name stands (bindings, parameters, labels, record fields, member access, map keys), so a field named length or if can be declared and read, and a backticked e reads a field while plain e stays Euler’s number. Argument-label words such as length, e or abs also name record fields and members without backticks.

  • Extension functions declared with Swift @GesFunction or C# [GesFunction] may take one GesRandomGenerator parameter in any position, which receives the call’s seeded generator; it is no script argument and does not count toward labels, arity or C#’s four-parameter limit.

  • Packed schemas: packed schema :Name or packed(8|16|32|64) schema :Name declares a record of fixed-width fields (integers and stepped numbers with fixed ranges, Booleans, closed Tags, Flags, other packed schemas) of at most 64 bits, schema.packedField and schema.packedTooWide otherwise. Its wire encoding is unchanged and equals the word in little-endian order; its delta changes the word as a whole. Generated code holds it as one word: a Swift struct over rawValue that is Hashable, Sendable and Codable, or a C# struct over RawValue, with checked field properties, checked and unchecked creation from a raw word, and Lists of them as arrays of words that read and write a word at a time. GesSchema.PackedWidth/PackedBits and GesBitReader.RemainingBits (Swift packedWidth, packedBits, remainingBits) are new.

  • ges schema generate --models <namespace> (GesSchemaGenerateOptions.Models): wire code shares the packed types of model code in that namespace and converts every wire record with a model directly to and from it, without GES values: C# ToModel()/CopyFrom(model), Swift toModel()/read(model:)/init(wire:), guarded by the schema hash.

  • Swift wire code generated with --namespace and --models converts to and from models at file scope, also in split files, and names wire and model types so that neither hides the other. A packed wire root shared with the models gets its wire members as static members of an enum <Name>Wire in the wire namespace, as C# does with its class, so that several wire generations of a module can share the model, with copy and quantize as in C#. A Swift file declares its namespace enums and then extends the whole namespace, as split files do, so that names of enclosing namespaces cannot hide the other side’s. --models naming the wire namespace itself, a namespace that continues the other side’s with the name of a type there (a <Name>Wire or a type of any model group included), a <Name>Wire that another type already names, a namespace starting with a Swift type name that generated code uses and, in Swift, a wire type or nested type that would hide a namespace the code names are generate.nameCollision; Swift namespaces of wire code with models and of its models start with an uppercase letter (generate.invalidNamespace).

  • Swift wire code with --models extends the namespace components it shares with the models’ namespace instead of declaring them again, and ges schema generate --extend-namespace <A> (GesSchemaGenerateOptions.ExtendNamespace) makes any Swift generation extend the leading part A of its namespace that another generation declares, so generations such as Game.World and Game.Panels, or two in Game, can share one module.

  • Both CLIs have bench, an in-process benchmark of a compiled program: it loads the program once, warms it up and times every further run of the entry message, then reports min, median, mean, p95, max and standard deviation, a checksum of the console output, and on .NET the allocations and collections per run and the tiering settings, as text or JSON. scripts/bench-compare.py compares the Swift CLI, the .NET JIT with and without tiered compilation, ReadyToRun and NativeAOT on the same binary.

  • :Bytes, an immutable byte sequence: literals :Bytes[0xa0, 183] and :Bytes("a0b7"), as :Bytes from integer Lists and hexadecimal Text, as :Text/parse/documents, count, in, indexing, iteration, equality and order, :take/:drop first/last slices, + concatenation and UTF-8 conversion with :Bytes(utf8: text) and :Text(utf8: bytes). Message JSON writes Bytes as Base64, schemas add :Bytes max n with generated WriteBytes/ReadBytes code, and the Bridges map C# byte[] and Swift [UInt8].

  • ges schema generate --model <group> --values gives every model type toValue() and init(value:) (C# ToValue() and FromValue(value)) with the plain Record that wire --values reads and writes, so models and wire records convert through one value instead of hand-written copies. A nested field that does not convert reports its path, such as entries[].level, as the wire value path does.

  • Schema union alternatives take labels, as in :Text max 64 | bind: :Loadout_UnitBind: generated code names the alternative .bind (C# Bind) instead of after its type; the label changes no bytes and no hash.

  • Schema tag sets tags :Mount as (#front, #rear): a field, list element or alternative of type :Mount is that :Tag(...) in place, with the same bytes and hash, and generated code declares one Mount enum for every field of it instead of one per field.

  • Schemas take the fields of another schema with with :Unit_Common, optionally all optional and without (id); an abstract schema only lends its fields. The record stays flat and hashes like written fields. Generated models adopt a protocol (C# interface) per schema they take unchanged; GesSchema.IsAbstract and Takes (Swift isAbstract, takes) describe it, and misuse of an abstract schema is schema.invalidAbstract.

  • Schema fields computed by an expression, as in script records: power: :Quantity(W) computed by 0W when duration <= 0s, otherwise energy / duration. The subset reads fields, lets and constants with arithmetic and comparisons in units, when … otherwise, min of, max of, clamp, abs, default, has value and list sums and counts; binding checks types and units, and the expression belongs to the hash. Computed fields are never encoded, decoding adds them, a document that sets one fails, and generated models and wire records give them as read-only properties that compute the bits of the virtual machine. GesSchema.ComputedFields (Swift computedFields) describes them; mistakes are schema.invalidExpression, and a required field that reads an optional field without has value or default is schema.computedMayBeAbsent. Generated code is plain binary64 and Boolean code in the language’s own operators, such as duration <= 0.0 ? 0.0 : energy / duration, with a small GesComputed helper type for the rules plain code lacks; only a field where whole numbers beyond 2^53 could meet keeps the exact-value helpers.

  • Computed fields may be spatial: :Vector, :Point, :Box, :Disc and :Poly, built with the constructors of scripts, as in size: :Vector(m) computed by :Vector(x: (arena.columns - 1) * arena.spacing, y: (arena.rows - 1) * arena.spacing) or bounds: :Box(m) computed by :Box(lower: origin, upper: origin + size). Later fields read their parts (size.x, bounds.center, zone.radius, shape.points[:count]), vectors and points take the arithmetic of the virtual machine, abs of a vector is its correctly rounded length, and :Poly(points:) takes a list of points, a list field of Points or a projection list[:select item => point]. Generated models and wire records give them as GesVector, GesPoint, GesBox, GesDisc and GesPoly properties.

  • A schema union may span lines: a | may end a line or start the next one, with comments and blank lines between the alternatives, in fields, arguments and List elements. ges schema format breaks a union before each further alternative once it no longer fits 100 columns or holds an axis block.

  • ges schema generate --model <group> --documents (option Documents) lets models read GES document text: each root gets C# FromDocument(text) (Swift init(document:)) and the generation a type that reads any root by its :Schema(:Name) header: Document inside the namespace, ModelDocument without one. The document is checked against the embedded schemas, defaults apply, and errors carry their document.* or wire.* code, line, column and field path; a missing or other header is the new document.schemaMismatch. The Runtime’s GesSchemaDocument does this for generated code, and GesDocumentException.Path (Swift GesDocumentError.path) names the field.

  • Schema type :Disc(unit) { x ..., y ..., radius ... } holds the geometry library’s GesDisc: its centre as a Point of the axes x and y, then its radius, binary64 without a block. The value path, documents ([center: ..., radius: ...]), deltas, dumps, generated wire code and models handle it like a Box.

  • Schema types :Box(unit) { ... } and :Poly(unit) max n { ... } hold the geometry library’s GesBox and GesPoly with per-axis constraints like :Point. A Box encodes its corners lower and upper as two Points and its value orders them; a Poly encodes its points in the plane z = 0 as a List of x and y. The value path converts the library’s external values, documents write a Box as the Map of its corners and a Poly as the List of its points, generated wire code holds GesBox and the reusable Points of a Poly with a GesPoly view, and models hold GesBox and GesPoly. The built-in names Box, Poly and Disc are reserved: a schema, message or message set of that name is schema.duplicateName.

  • Recursive schema Lists: units: :List(:Loadout_Bind) max 16 depth 3 in :Loadout_Bind holds records of that schema up to three deep, so a tree needs one schema instead of one per level. The wire encoding is that of one schema per level; a record deeper than the depth fails with the new wire.tooDeep, whose message names the depth, such as wire.tooDeep at 'units[].units[].units': deeper than depth 3 (GesWireException.Detail, Swift GesWireError.detail), and a document with document.tooDeep. Generated code of the recursive schema takes the level of each record; every other schema generates the same code as before. GesSchemaType.Depth (Swift depth) describes it. The element may also be a union of scalars and the schema itself, units: :List(id: :Text max 64 | bind: :Loadout_Bind) max 16 depth 3, so a document writes a unit as its id alone or as a bind; at the depth the List holds neither.

Changed

  • A power with the exponent 0.5, as sqrt and √ compute it, is now the correctly rounded square root in both virtual machines, so its bits no longer depend on the platform’s pow.
  • Host.Load and the writer no longer validate a Program again that the Reader, the Compiler or an earlier validation already accepted, so loading one Program into many hosts costs no repeated pass. A VM reset clears only the registers the last handler used instead of the whole register file.
  • C# writes an extension’s result into its destination register when the call returns, as Swift does, instead of during the call. GesValueArguments is valid only during the extension call: C# throws InvalidOperationException and Swift reads it as empty with Nothing items when it is kept longer.
  • The GesRuntimeLimits documentation states what each limit counts; the unused call-depth bookkeeping of the runtime budget is gone. Swift GesValue and GameEventScriptMessage document why they are not Sendable and how to forward a message across isolation domains as a JSON snapshot.
  • Swift Syntax, Runtime and Compiler no longer use Foundation. The Card Lab WebAssembly module shrinks from about 71 MB to about 19 MB. Highlighting the shared corpus is about 20 times faster in Swift and 3.5 times faster in C#.
  • A delayed emit after … without recipients now behaves like the same emit without after: it is not scheduled and is observed as not queued, so it no longer keeps the host waiting, counts towards the queue limit or appears in NextMessageDelay. Its script result stays true. Delayed publishes are still scheduled for the outbound sink.
  • The root SwiftPM package now exposes only the four libraries. Build ges from implementation/swift/GameEventScriptTool, or install it via Homebrew, the install script or standalone downloads. The root macOS minimum is now 10.15; the separate CLI retains its 10.15.4 minimum.
  • Swift GameEventScriptProgram is now an immutable final class, so hosts and callers share a single Program instance. Program contents, binary encoding and copy-on-write isolation of returned arrays are unchanged.
  • Script handlers execute faster in both runtimes. Integer arithmetic and integer range loops write results in place, constant map literals and data constructions no longer redo per-execution work, and sorting numeric keys is no longer quadratic. The Swift VM additionally mutates registers in place without per-access exclusivity checks or reference counting on integer paths. Behavior and results are unchanged.
  • Both compilers move loop-invariant constant loads and arithmetic in front of their loop, so loops execute fewer instructions. Random draws, messages and host calls stay in place and results are unchanged; executed opcode counts drop and register requirements can grow slightly.
  • The C# and Swift compilers now produce byte-identical Programs for the same sources and compilation options, including debug symbols, source maps and source archives. Only BuildMetadata differs to identify the producing compiler.
  • The Swift compiler now writes the BuildMetadata section with compiler ID steph.ges.compiler.swift and version 0.1.0, as the binary format requires of every port. Runtime behavior does not depend on it.

  • Workflow container images are pinned by digest and every job has a timeout.

  • Swift list + value and zip check MaxValueDepth like every other construction, where a deep fold crashed the Swift process. C# Bytes answer :contains any, :contains all, [:first], [:last] and [:single] as Swift does, and C# external type constructors take Bytes parameters.

  • The C# CLI writes a script’s output to a redirected file at the shared offset, so a later writer no longer overwrites it, and it formats canonical decimals, schema hashes and generated code culture-invariantly, where a locale with the minus sign U+2212 changed them. bench --entry initialization is cli.missingEntry instead of a crash.

  • The Swift compiler assigns binding IDs per kind with counters, as C# does, instead of in quadratic time.

  • The DLLs in the C# packages carry the time of the packed commit, or the current time for uncommitted changes, instead of a fixed date, so MSBuild’s copy into a build output replaces the DLL of an older package version of the same size.

  • A unary intrinsic with a parenthesized operand, such as floor(x), and an intrinsic call such as atan2(y, x) are power bases in both ports: floor(x) ^ 2 is (floor x) ^ 2. C# rejected both, and Swift accepted -x² ^ 2 and floor x² ^ 2, which are syntax errors.

  • Swift: let pulse be pulse() calls the function pulse instead of binding the new local as a Handler, and an alias of a Handler binding keeps its signature, so a call through it with a mismatched label yields nothing, as in C#.

  • :Number(0, "s") and other literal time units are accepted as send delays.

  • Floating Range selectors (take/drop first/last, highest/lowest, :reverse, :sort) return exactly the items of the materialized List; when no Range reproduces them, they return a List.

  • :sort, :order by and :take/:drop highest/lowest order integers beyond 2^53 exactly, as < and > do.

  • Message JSON readers reject \u escapes that are not exactly four ASCII hex digits, such as \u+061.

  • Generated models read a document union as the alternative its schema check chose, also inside explicit :List and :Record forms.

  • Swift generation with --models no longer fails on an optional union without a :Nothing alternative, and the Swift direct wire-to-model conversion keeps an absent field absent when it defaults to a sibling.

  • An empty packed schema generates compiling C# and Swift code, and a packed root field named like a wire member, such as encoded, is generate.nameCollision.

0.4.0 — 2026-10-11

Added

  • Compact nested loops, such as for suit in suits and rank in ranks { ... }, with the same ordering and scope as ordinary nested loops.

Multiple bindings work in loops and selectors; compact [:entries :filter ... :select ...] chains avoid repeated brackets. Release documentation defines platform evidence and separate, revision-bound performance qualification without extra native Swift PR builds.

Changed

  • sum and average are strictly numeric, including singleton collections. Nonnumeric values make the result nothing; later projections still execute. Numeric strings are not converted implicitly. Use explicit conversions for numeric text and fold for concatenation.
  • Combined collection sources evaluate every source expression once from left to right before validation, including invalid combinations. Construction no longer creates preliminary validation iterators.
  • Qualified extension names must be contiguous (:namespace.name).
  • Opcode values 0xF8..0xFF are reserved for local experiments and rejected by standard compilers, validators and runtimes; they are not a plugin ABI.

Fixed

  • C# distribution smoke tests use fresh build and restore directories, preventing stale reproducible DLLs from a prior version contaminating package validation.
  • Program validation rejects internal VM values escaping into script-visible data, including through inline assembly control flow.
  • Swift compiler lowering now matches C# for constant Text-key access, collection guard branches and short-circuit expressions. Adjacent source mappings are compacted; inlined constants are attributed to their use sites.

  • Card Lab browser assets and workers share a build version to prevent mixed cached revisions, including stale dump requests. Dump source names follow the loaded game instead of always using rules.ges.
  • Removed Card Lab folding entries accidentally inserted into the historical 0.2.0 and 0.3.0 notes; that feature belongs to this development release.

Performance

  • Swift uses compact value storage, inline dispatch and owner-local typed register writes, reducing register access and value-copy overhead while preserving exact Int64 arithmetic, units and runtime access checks. Dice sums use cached numeric storage; collection counts stay in payloads. Numeric operations use register fast paths. Profiler timestamps are captured at callback boundaries.
  • C# single binders no longer allocate binding lists, and binding metadata is stored only on relevant AST nodes. Swift normal iterators reuse fixed operand descriptions during validation.
  • Reviewed profile-specific reference updates distinguish deliberate storage and safety-validation costs from avoidable allocations. All zero-dispatch allocation budgets remain zero. See the performance review.

  • Collection selectors [:fold acc be seed, value => expression] and [:reduce acc, value => expression] accumulate values in iteration order. An empty fold returns its seed; an empty reduce returns nothing.
